# 함께 계획 세우기

작업 계획을 사용자와 질문·답변으로 구체화한다.

- 사용자가 요청한 범위 안에서만 계획하고 작업하며, 임의로 범위를 넓히지 않는다.
- 요청한 일을 완료하는 데 꼭 필요한 연관 작업이 있으면, 먼저 사용자에게 설명하고 진행 여부를 물은 뒤 승인받은 범위에서만 진행한다.
- 코드·문서에서 확인할 수 있는 사실은 직접 조사한다. 모호한 요구나 결정이 필요한 사항은 사용자에게 질문한다.
- 사용자에게 질문할 때는 항상 선택 UI를 사용한다. 필요한 설명·근거·추천 이유는 UI를 띄우기 전에 전달하고, 일반 메시지의 번호 목록으로 질문을 대신하지 않는다. 추천안을 사용자 결정으로 대신하지 않는다.
- 선택 UI를 띄우기 전에 **각 선택의 동작 방식, 기대 효과와 단점, 필요한 변경·작업량, 예상 소요 시간**을 사용자가 비교할 수 있게 설명한다. 새 파일·설정·운영 절차가 생기는지도 알린다. 예상 시간은 근거와 전제에 따른 범위로 제시하고, 불확실하거나 아직 추정할 수 없는 부분은 명시한다.
- 선택 UI를 띄운 뒤에는 사용자가 답변할 때까지 대기한다. 추가 설명·진행 보고·최종 답변이나 다른 작업을 이어가 UI가 사라지게 하지 않는다. 비동기 UI라면 대기 도구로 기다리고, 답변을 받은 뒤 재개한다.
- 지금 답할 수 있는 질문부터 묻고 답을 기다린다. 앞선 답에 따라 달라지는 질문은 그 답을 받은 뒤 묻는다.
- 요청한 작업에 필요한 만큼만 계획한다. 과도한 추론이나 미래 가정으로 설계를 확대하지 않는다.
- 답변으로 결정된 내용을 계획에 반영한다. 필요한 결정이 남아 있으면 질문을 이어가고, 사용자와 계획에 합의하면 마친다.
- 계획 합의 후 승인된 작업을 worker에게 요청할 때는 host에 맞는 스킬을 사용한다.
  Codex host는 `collaboration-with-claude`, Claude Code host는 `collaboration-with-codex`.
